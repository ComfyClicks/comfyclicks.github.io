Docketeer

From severity counts to CVE investigation.

I worked with a team of engineers to transform Docketeer’s existing Docker image scanner from a high-level severity counter into a comprehensive vulnerability-analysis experience, carrying detailed findings across the backend, application state, persistence layer, and interface.

The opportunity

The scanner knew more than the interface showed.

Docketeer 17 already used Grype to scan Docker images. It parsed package names, installed versions, vulnerability IDs, and severities—but then reduced those records to four aggregate counts and discarded the detail.

I saw a more useful product hiding in that data: preserve every finding, then let developers move from a portfolio-level signal to the affected image, package, and individual CVE.

End-to-end engineering

One detailed record.
Six connected layers.

The core challenge was not adding another scanner. It was preserving Grype’s row-level results across an inherited architecture without breaking the fast summary experience already in use.

  1. 01 · ScanGrype

    Scan every local Docker image and parse package, installed version, vulnerability ID, and severity.

  2. 02 · ServeExpress

    Return both severity counts and complete vulnerability rows through the existing image API.

  3. 03 · CacheRedis

    Preserve the latest results and timestamp; let a user-triggered rescan bypass and replace the cache.

  4. 04 · ModelRedux Toolkit

    Group findings into six severities, calculate totals, and derive the most affected packages.

  5. 05 · ExploreReact + Chart.js

    Connect summaries, image cards, record tables, filters, NVD links, and interactive charts.

  6. 06 · CompareMongoDB

    Save full scan snapshots through Mongoose and build a time-series history across images.

Working in the open

An inherited codebase.
A real release handoff.

Docketeer 18 extended an established open-source codebase and was released through the Open Source Labs project.

My work touched backend controllers, API routes, cache middleware, Redux state, React and TypeScript components, MongoDB persistence, Docker configuration, tests, and release documentation. Later Docketeer contributors inherited and continued evolving the architecture.
